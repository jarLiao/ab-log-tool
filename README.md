# AB 日志分析

在浏览器本地解析 AndroidTool 的 AB 日志，查看最终缺号、乱序补到、重复记录、同号不同内容、待核对的序号跳变，以及原始与过滤日志的差异。

这是可导入真实日志的网页工具。部署到 GitHub Pages 后，用户打开网址即可使用；无需安装客户端、注册账号或上传日志。

在线使用：[AB 日志分析](https://jarliao.github.io/ab-log-tool/) · [GitHub 仓库](https://github.com/jarLiao/ab-log-tool)

## 使用

1. 点击“导入日志”，选择“原始接收”“过滤之后”或“两份配对”。
2. 点击文件区域选择日志，或将文件拖入对应区域；配对日志应来自同一设备、同一次连续连接。
3. 点击“开始分析”。处理过程中显示进度，支持取消。
4. 查看统计和序号图。普通报文与异常标记均可点击，查看真实源行和解析；图表概览选中最近的采样点，局部放大或使用左右方向键、上一 / 下一报文可逐包查看。重复、同号不同内容、配对记录保留关联原文。
5. 使用类型、序号、源行、时间和命令筛选。图表支持局部查看、放大、缩小及移动范围。
6. 导出 CSV 明细和 TXT 原始片段。默认包含全部文件异常与配对差异，也可以仅导出当前视图和筛选结果。

“体验演示”使用程序生成的数据，通过同一套解析引擎运行。发布文件没有内置用户的原始日志。

## 序号与原文怎样对应

列表和详情默认以 HEX 为主，同时显示十进制值。图表右上角的“序号显示”可以切换为十进制优先，不会改变统计结果；搜索支持 0x8404 或 33796。

AB 序号位于帧内第 7、8 字节（从 0 计偏移 6、7），低字节在前。例如：

~~~text
原文字节 04 84 → 序号 0x8404 → 十进制 33796
~~~

选择异常后，原文上方显示这一转换关系和完整 8 字节帧头；黄色标记指出原文中的两个序号字节。点击“定位字节”或帧头中的低 / 高字节，可以跳到准确位置。分片跨行、一行包含多个帧、消息体恰好包含相同字节时仍按解析位置定位。

原文区域可以滚动浏览完整日志，支持首行、末行、行号跳转及回到选中行。点击任一行，上方的序号映射、帧头、命令 / Key 和来源信息随之切换；跨行分片会选中对应的完整帧，一行有多个帧时可分别选择。诊断文字、空行或损坏行没有可信报文时清空解析，保留原文。查看关联原文中的其他报文后，可用“返回异常”恢复原异常及其关联片段。复制片段包含当前报文的命令 / Key。

长日志按可见范围加载，滚动范围覆盖整个文件；不会把几十万行一次性放进页面。行号在横向滚动时保持可见，方向键可选择相邻行，Home / End 可选到首尾。查看普通报文不会改变异常统计或将其加入异常 CSV。

详情和每份关联原文的帧头下方显示“与上包间隔”，同时给出上一有效报文的序号与源行；局部图表的普通点提示、复制片段和 CSV / TXT 也保留这一信息。以同一日志中当前有效报文与上一有效报文的接收时间相减，不按序号排序，也不受命令筛选影响。超过 1 秒同时显示秒值；首包显示“—（首包）”，同时间戳显示 0 ms，负值提示时间戳回退。分片使用起始片段的接收时间，跨段仍保留实际时间差；这表示日志接收间隔，不是设备采样周期或蓝牙空口时延。

缺号没有原始报文，界面分别显示缺号范围之前和之后实际存在的报文，避免把邻近报文的序号当成缺失序号。CSV 保留十进制字段，并增加序号 HEX、序号原始字节 LE、缺号起止 HEX；TXT 和复制片段也包含对应关系，原始文字保持不变。

## 连接与重连核对（1.5.0）

导入 abBle / abFilter 时可附加 bleConnection 日志，也可选择“仅连接诊断”。左侧“连接时间线”显示连接尝试、链路连接、就绪、断开、重试、错误码及首次有效报文。点击事件进入完整原文；相同镜像事件同时保留两份文件的位置。恢复概要分别列出断开到就绪的时长，以及日志是否观察到后续有效报文。

报文按真实连接边界停止组包并重新统计序号，序号图在边界处断线并可点击。已有的上包间隔仍保留实际接收时间差，跨连接时单独说明。配对页新增按连接汇总，无法唯一关联的报文归入待核对；只有明确匹配的 reorder_skip 才附为过滤决策证据。

三份日志可一起保存到本机历史，恢复时按当前规则重新分析。全部结果 CSV/TXT 包含连接事件、连接编号、原文位置与相关片段；也可以只导出当前连接事件筛选。规则、兼容边界和示例见 [连接分析说明](docs/连接分析.md)。

1.5.1 将图上的“连接边界”更名为“连接区间切换”，表示两段有效报文之间的切换位置。断开、就绪和会话结束记录另按当前文件的原文位置标注；最后一条报文之后的断开也会显示，并注明“本文件此后无有效报文”。图下列出连接记录和本段首包的日期、毫秒时间与可点击行号，明确区分就绪和实际再次收到报文。横轴仍为报文顺序，断开期间不按时长留白；这些展示不改变分段、缺号或重复统计。

## 数据格式与判定

- 日志记录为“毫秒时间戳,十六进制报文”；允许空行、诊断文字、十六进制字节间空白。
- 支持 UTF-8（含 BOM）、带 BOM 的 UTF-16LE / UTF-16BE，以及 UTF-8 解码失败时的 GB18030。
- AB 帧头 8 字节；长度、CRC 和序号按小端读取。CRC16 只校验消息体，采用多项式 0x1021、初值 0，与当前 AndroidTool 源码一致。
- 支持完整帧跨多行、单行包含多个帧。CRC 错误、非法十六进制、长度不符及残帧单独列示，保留原文，不让不可信序号参与连续性统计。
- 所有命令共用 16 位序号，严格按原始行顺序分析。后续补到的序号不计入最终缺号；日志首尾范围之外不补缺号。
- 同一周期内，序号和完整帧均相同为重复；序号相同但内容不同单列。正常 65535 → 0 回绕不会误判为乱序。
- 周期采用距离当前最大已见序号最近的候选解释，不能据此确定实际前进或回退。恰好相差半周期，或候选序号向已观测范围之前倒退超过 4096 时，列为“序号跨度待核对”，切分可分析段，不计算跨段缺号。较小范围的开头补到扩展同段观测范围；周期是相对编号，开头补到上一周期时可以为 -1。这是有明确边界的保守策略，不保证还原任意大跨度缺失或跨多周期迟到。
- 序号跳变单独识别：最近周期的候选解释发生向后回退，随后至少 4 条记录连续递增；若候选序号位于本段起点之前且距已见最大值超过 4096，或随后最多 8 条中至少 3 个已出现序号带有此前未见的完整帧内容，则标记“序号跳变待核对”并开始新段。这些阈值是工程默认值，不是设备协议要求，也不能证明方向或设备重启。正常补齐缺口、完整帧原样重放、孤立的同号异内容仍按原规则统计。
- 跳变详情分别展示观测值与待核对状态。例如 9492 → 47995 显示“数值增大 38503，方向待核对”；按 16 位循环序号，向前跨越 38503 与向后跨越 27033 都是候选解释。48324 → 47996 显示“数值减小 328，原因待核对”。数值变化和候选跨度均不等于丢包数量。
- 不同段之间不互相填补缺号或累计同号异常。出现分段后，界面显示“段内最终缺号”、待核对提示和各段的原文范围；**段内缺号为 0 不代表整份日志完整**。跳变明细保留前后序号、HEX 与原文字节，CSV / TXT 明确标出“段间待核对”。CSV 使用“前一报文序号”“序号数值变化”“判定提示”“候选向前跨度”“候选向后跨度”，不将候选距离称为回退幅度；数值变化保留正负号。序号重置、重用与数据重放的具体原因需要设备端记录确认。
- 缺号只表示这份日志的缺口，不能直接证明蓝牙丢包。过滤日志的缺号可能来自正常过滤。
- 配对使用接收时间戳和完整帧，按出现次数逐个匹配；展示单侧记录、共有帧顺序差异、共有时间范围之外的差异。相同时间戳和完整帧多次出现时，数量差异可确定，逐条对应关系列为待核对。
- Key 展示消息体偏移 2 的字节（如果存在），具体语义仍取决于命令结构；本工具不解码全部命令业务内容。

输入以单设备的一次记录任务为前提，可以包含多次重连。有序会话标记、应用启动或旧版连接状态提供分段证据；没有连接证据时，无法确认连续性的序号跳变仍保守分段。不能还原任意多设备混合、缺乏标记的连接拼接及所有短回退。每份最多 128 MB；本次验收覆盖约 50 MB 单文件及两份约 50 MB 的配对。

## 本地处理与运行

网页没有后端、遥测、外部字体或外部脚本。日志由 Web Worker 解析，界面只接收统计、当前页和局部图表；完整原始文件可保存在本机历史，不上传服务器。

导入窗口默认勾选“分析完成后保存到本机历史”，可以取消，也可以在分析完成后手动保存。顶部“本机历史”支持按文件名搜索、重新打开、删除单条和清空记录；每条显示来源、文件大小、最近打开时间和上次分析概要。一个配对任务同时保存两份日志，重新打开后按当前版本重新分析，避免继续使用旧版计算结果。

历史使用本站当前浏览器的 IndexedDB，元数据与文件在同一事务内保存和删除。正常浏览器关闭、重新打开后仍可恢复；清除本站数据、关闭无痕窗口或浏览器回收存储可能删除历史，请保留日志原件。这不是跨浏览器或跨电脑同步；网页文件缓存与日志历史也相互独立。存储机制参见 [MDN IndexedDB 说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)。

工程默认最多保存 20 个任务、日志合计 512 MB；达到上限时保留已有记录并提示清理，不自动淘汰。浏览器实际配额不足或禁止存储时提示保存失败，当前分析与导出仍可使用；释放空间后可重试保存。Chrome / Edge 中按文件角色、文件名和内容 SHA-256 识别重复导入；相同任务更新一条历史，同名但不同内容保留为不同任务。演示、取消或分析失败的任务不保存。未勾选且未手动保存的日志只保留在当前页面。

首次打开网址需要下载网页资源；页面加载后可断网导入、分析和导出。没有实现离线缓存，因此不保证断网后重新打开网址可用。

最终用户建议使用新版 Chrome 或 Edge。可以直接打开 dist/index.html 验证本地版本；开发预览运行：

~~~text
npm start
~~~

打开终端输出的本地地址，默认 http://127.0.0.1:4178。项目没有 npm 运行依赖，不需要安装依赖包；Node 只用于开发预览和验证，网站用户不需要安装。

## 发布到 GitHub Pages

本项目已发布到 [https://jarliao.github.io/ab-log-tool/](https://jarliao.github.io/ab-log-tool/)。仓库为 [jarLiao/ab-log-tool](https://github.com/jarLiao/ab-log-tool)，Pages 已选择 GitHub Actions。

.github/workflows/pages.yml 会在每次向 main 推送更新时，先运行引擎测试和静态检查，再发布 dist/。也可以在 [Actions](https://github.com/jarLiao/ab-log-tool/actions/workflows/pages.yml) 手动运行 **Validate and deploy GitHub Pages**。本地验收日志、截图和导出结果不在源码提交或发布文件中。

部署到另一个仓库时，将源码推送到 main，在 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**，再运行同一工作流即可。

所有资源使用相对路径，适用于“用户名.github.io/仓库名/”形式的项目站点。

也可以采用分支发布：将 dist/ 内的文件放到专用发布分支根目录，并在 Pages 中选择该分支。不要把项目源码根目录直接当作网页入口。

配置依据：[GitHub 官方 Pages 工作流说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 验证与维护

~~~text
npm test
npm run check
~~~

引擎测试使用独立 CRC 编码器生成日志，覆盖补到、周期、重复内容、序号跳变与分段、分片、损坏数据、导出以及配对。设置环境变量 AB_RAW_LOG、AB_FILTER_LOG 后，还会验证两份配对样本的已知结果；AB_ROLLBACK_LOG 可指定包含跳变的样本，供引擎与浏览器共同回归。真实样本由本机提供，不在仓库中。

tests/browser.cjs 使用 Playwright 进行浏览器验收；需要本机可用的 Playwright。可用 AB_PLAYWRIGHT_PATH 指定已有安装，AB_BROWSER 指定浏览器，AB_PREVIEW_URL 指定开发预览地址；默认使用本机 Chrome 和 4178 端口。它会在忽略的 artifacts/ 中生成规模日志、截图和验证记录。

tests/inspection.browser.cjs 使用相同环境变量，检查普通报文、完整日志滚动、点击行后的字段同步、多帧选择、关联原文返回、键盘操作及浏览器滚动高度限制。若 artifacts/ 已有规模测试生成的 50 MiB 日志，也会检查其末行定位。

tests/jump.browser.cjs 使用合成数据验证序号数值增大、减小两类边界，检查卡片、图例、详情、原文字节和导出用语；同时验证普通报文切换后清除边界专属字段。环境变量与其他浏览器脚本相同。

tests/connection-markers.browser.cjs 检查区间切换、末尾断开、连接事件日期与原文定位、键盘、缩放、密集标注和窄屏布局。可设置 AB_CONNECTION_LOG 指向本机已知的 19,981 帧回归样本；不设置时仅使用合成日志。私有样本和截图只写入已忽略的 artifacts/。

tests/history.browser.cjs 使用隔离的浏览器目录验证上包间隔、保存与重开、完整浏览器重启、配对恢复、重复导入、存储失败后的重试、原子删除与容量上限。若已有 generated-50MiB.txt，会额外验证大文件跨浏览器重启的恢复与末包定位；AB_SKIP_HISTORY_LARGE=1 可跳过该规模项。测试数据均为合成文件，证据保存在忽略目录 artifacts/。

scripts/benchmark.cjs 以日志路径为参数，可单独测量解析耗时和 Node 解析进程峰值常驻内存。

详细结果见 [验证记录](docs/验证记录.md)。主要文件：

| 文件 | 用途 |
| --- | --- |
| dist/index.html、style.css | 导入、统计、图表、列表与原文界面 |
| dist/engine.js | 帧解析、序号判定、配对、原文定位和导出 |
| dist/worker.js | 后台处理、分页查询和导出请求 |
| dist/history.js | 本机历史元数据和原始文件的事务存储 |
