# AB 日志分析

在浏览器本地解析 AndroidTool 的 AB 日志，查看最终缺号、乱序补到、重复记录、同号不同内容，以及原始与过滤日志的差异。

这是可导入真实日志的网页工具。部署到 GitHub Pages 后，用户打开网址即可使用；无需安装客户端、注册账号或上传日志。

## 使用

1. 点击“导入日志”，选择“原始接收”“过滤之后”或“两份配对”。
2. 点击文件区域选择日志，或将文件拖入对应区域；配对日志应来自同一设备、同一次连续连接。
3. 点击“开始分析”。处理过程中显示进度，支持取消。
4. 查看统计和序号图。点击异常标记或列表记录，查看带真实行号的原始片段；重复、同号不同内容、配对记录同时列出关联原文。
5. 使用类型、序号、源行、时间和命令筛选。图表支持局部查看、放大、缩小及移动范围。
6. 导出 CSV 明细和 TXT 原始片段。默认包含全部文件异常与配对差异，也可以仅导出当前视图和筛选结果。

“体验演示”使用程序生成的数据，通过同一套解析引擎运行。发布文件没有内置用户的原始日志。

## 数据格式与判定

- 日志记录为“毫秒时间戳,十六进制报文”；允许空行、诊断文字、十六进制字节间空白。
- 支持 UTF-8（含 BOM）、带 BOM 的 UTF-16LE / UTF-16BE，以及 UTF-8 解码失败时的 GB18030。
- AB 帧头 8 字节；长度、CRC 和序号按小端读取。CRC16 只校验消息体，采用多项式 0x1021、初值 0，与当前 AndroidTool 源码一致。
- 支持完整帧跨多行、单行包含多个帧。CRC 错误、非法十六进制、长度不符及残帧单独列示，保留原文，不让不可信序号参与连续性统计。
- 所有命令共用 16 位序号，严格按原始行顺序分析。后续补到的序号不计入最终缺号；日志首尾范围之外不补缺号。
- 同一周期内，序号和完整帧均相同为重复；序号相同但内容不同单列。正常 65535 → 0 回绕不会误判为乱序。
- 周期采用距离当前最大已见序号最近的解释；恰好相差半周期，或向已观测范围之前倒退超过 4096 个序号时，列为“序号跨度待核对”，切分可分析段，不计算跨段缺号。较小范围的开头补到扩展同段观测范围；周期是相对编号，开头补到上一周期时可以为 -1。这是有明确边界的保守策略，不保证还原任意大跨度缺失或跨多周期迟到。
- 缺号只表示这份日志的缺口，不能直接证明蓝牙丢包。过滤日志的缺号可能来自正常过滤。
- 配对使用接收时间戳和完整帧，按出现次数逐个匹配；展示单侧记录、共有帧顺序差异、共有时间范围之外的差异。相同时间戳和完整帧多次出现时，数量差异可确定，逐条对应关系列为待核对。
- Key 展示消息体偏移 2 的字节（如果存在），具体语义仍取决于命令结构；本工具不解码全部命令业务内容。

每份文件按一次连续连接处理，不支持多设备混合、重启后序号复位或多段连接拼接。每份最多 128 MB；本次验收覆盖约 50 MB 单文件及两份约 50 MB 的配对。

## 本地处理与运行

网页没有后端、遥测、外部字体或外部脚本。文件留在当前页面的内存中，由 Web Worker 解析；界面只接收统计、当前页和局部图表。刷新或关闭页面后，日志与结果清除。

首次打开网址需要下载网页资源；页面加载后可断网导入、分析和导出。没有实现离线缓存，因此不保证断网后重新打开网址可用。

最终用户建议使用新版 Chrome 或 Edge。可以直接打开 dist/index.html 验证本地版本；开发预览运行：

~~~text
npm start
~~~

打开终端输出的本地地址，默认 http://127.0.0.1:4178。项目没有 npm 运行依赖，不需要安装依赖包；Node 只用于开发预览和验证，网站用户不需要安装。

## 发布到 GitHub Pages

仓库尚未创建，本交付没有发布公网地址。已提供 .github/workflows/pages.yml，只上传 dist/，不会上传本地验收日志、截图或导出结果。

1. 创建用于这个工具的 GitHub 仓库，将本项目源码推送到 main 分支。
2. 在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。
3. 在 **Actions** 运行 **Validate and deploy GitHub Pages**，或向 main 推送一次更新。
4. 工作流通过引擎测试和静态检查后，发布 dist/；完成页显示访问网址。

所有资源使用相对路径，适用于“用户名.github.io/仓库名/”形式的项目站点。

也可以采用分支发布：将 dist/ 内的文件放到专用发布分支根目录，并在 Pages 中选择该分支。不要把项目源码根目录直接当作网页入口。

配置依据：[GitHub 官方 Pages 工作流说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 验证与维护

~~~text
npm test
npm run check
~~~

引擎测试使用独立 CRC 编码器生成日志，覆盖补到、周期、重复内容、分片、损坏数据、导出以及配对。设置环境变量 AB_RAW_LOG、AB_FILTER_LOG 后，还会验证用户提供样本的已知结果。

tests/browser.cjs 使用 Playwright 进行浏览器验收；需要本机可用的 Playwright。可用 AB_PLAYWRIGHT_PATH 指定已有安装，AB_BROWSER 指定浏览器，AB_PREVIEW_URL 指定开发预览地址；默认使用本机 Chrome 和 4178 端口。它会在忽略的 artifacts/ 中生成规模日志、截图和验证记录。

scripts/benchmark.cjs 以日志路径为参数，可单独测量解析耗时和 Node 解析进程峰值常驻内存。

详细结果见 [验证记录](docs/验证记录.md)。主要文件：

| 文件 | 用途 |
| --- | --- |
| dist/index.html、style.css | 导入、统计、图表、列表与原文界面 |
| dist/engine.js | 帧解析、序号判定、配对、原文定位和导出 |
| dist/worker.js | 后台处理、分页查询和导出请求 |
| dist/app.js | 页面操作、图表绘制和任务生命周期 |
| .github/workflows/pages.yml | 检查并发布 GitHub Pages |

源码与可发布文件分开存放。修改 dist/ 中的代码即可；此版本无需编译步骤。
