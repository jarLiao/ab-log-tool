# AB 日志分析网页需求说明

版本：1.5；日期：2026 年 9 月 11 日。

根据本次访谈，交付形态已由 Windows 免安装桌面程序调整为纯前端工具网页，目标部署方式为 GitHub Pages。算法、配对和导出要求沿用此前确认的范围。

## 已确认范围

| 项目 | 要求 |
| --- | --- |
| 输入 | 导入已有日志，浏览器本地分析。每次处理一个任务，支持单文件或一组配对文件。 |
| 数据规模 | 几百 KB 到几十 MB；按约 50 MB 单文件与一组同规模配对进行验收。 |
| 日志来源 | abBle 是蓝牙原始接收，abFilter 是过滤后日志；配对文件来自同一设备、同一次连接。 |
| 独立分析 | 两类日志均可独立分析。 |
| 消息序号 | 全命令共用一个递增序号；支持 16 位正常回绕。 |
| 最终缺号 | 完整分析范围内始终未出现的序号。后续补到不计为最终缺号。 |
| 乱序 / 重复 | 检测乱序补到、完整帧重复；同号不同内容单独列出。 |
| 原文定位 | 保留真实文件名、源行及关联记录，能从异常和图表找到原始片段。 |
| 普通报文浏览 | 正常报文也可从序号图点击查看，支持相邻报文与键盘导航；不改变异常统计。 |
| 完整日志浏览 | 原文区支持滚动整个文件和行号跳转。选中行后同步序号字节映射、帧头、命令 / Key；一行多帧提供选择，非有效报文行清空解析。 |
| 图表 | 展示接收记录顺序与消息序号，可看缺号、乱序、重复位置，并局部放大。 |
| 序号锚点 | 对齐界面序号与十六进制日志：HEX / 十进制双显、小端字节映射、原文序号字段高亮；分片与单行多帧保持准确位置。 |
| 导出 | 异常明细 CSV 与相关原始日志片段 TXT。 |
| 配对口径 | 用户选择 1C：只显示差异，由用户判断原因，不要求填写过滤规则，也不自动推断过滤原因。 |
| 连接前提 | 原约定为单设备、一次连续连接。9 月 11 日样本出现持续回退，用户不确定当时是否重连、重启或重新开启上传；工具须保留原因不确定性，不能强行将其认定为补包或设备重启。 |
| 跳变与统计边界 | 无法确认连续性的序号跳变标记待核对，保守划分分析段，展示前后序号、实际数值变化及源行；只计算各段内部缺号，段间缺失数量未知。分段概要、图表、明细与导出使用同一口径，边界处数不是丢包数量。 |
| 发布方式 | 用户授权部署到 GitHub Pages；独立仓库 jarLiao/ab-log-tool，访问 [AB 日志分析](https://jarliao.github.io/ab-log-tool/)，向 main 推送更新后自动检查并发布。 |

## 工程默认规则

- 源行顺序决定接收顺序；时间戳只用于定位和配对。展示筛选不会重算序号链。
- 解析协议帧而非将一行视为一包；支持跨行分片和单行多帧。
- CRC / 长度等无法可靠解析的帧单独报告，不让其中的序号污染有效报文统计。
- 从实际可观察到的报文确定缺号范围，不推算日志边界以外的序号。
- 周期以最近的序号距离作为候选解释，不能据此确认实际前进或回退。恰好相差半周期，或候选序号向已观察范围之前回退超过 4096 时保守分段并标记待核对，跨段不计算缺号。此阈值是实现默认值，并非用户要求的设备性能参数。
- 序号跳变识别采用保守的工程规则：最近周期的候选解释向后回退后，至少 4 条连续递增；同时候选序号位于本段起点之前且距已见最大值超过 4096，或其后最多 8 条连续帧中，至少 3 个序号已出现但带有未见过的内容。命中时开始新段，标为“序号跳变待核对”。这是针对计数连续性不足的处理，不是重启检测协议；短回退与复杂重放可能无法唯一解释。
- 数值变化直接计算为当前原始序号减去前一原始序号，与周期候选解释分开。9492 → 47995 显示数值增大 38503、方向待核对，不能因较短候选距离为向后 27033 就写成实际回退；48324 → 47996 显示数值减小 328、原因待核对，不推断设备重启。恰好半周期的两个方向同样都待核对。
- 普通缺口后续补到保持原判定，完整帧相同的重放仍记为重复，孤立同号不同内容仍单列。前一段出现过某个序号不能填补后一段的缺口。
- 有分段时，缺号卡片必须标明“段内最终缺号”，明确段内为 0 不等于整份文件完整；可展开各段源行、序号起止、报文数和缺号数，图表不跨段连线。跳变明细显示前后 HEX / DEC 并支持用任一序号搜索。
- 同一周期同号同完整帧是重复；同号但完整帧不同单列，二者不累计为丢包。
- 配对依据原接收时间戳与完整帧，逐个匹配出现次数。重复对应不能唯一确定时保留数量事实并提示待核对。
- 配对除单侧记录外，也展示双方都有、共有帧相对顺序差异，以及共有时间范围外的差异。
- 缺号只表示日志中的缺口。过滤后缺号可能来自正常过滤，不直接判断蓝牙链路实际丢包。

## 使用与交付

导入 → 进度与取消 → 统计和图表 → 异常与原文联动 → CSV / TXT。

CSV 使用 UTF-8 BOM 与中文表头。TXT 默认包含关联记录前后各 5 行；界面按可见行展示完整日志，TXT 导出保留全部关联源行。默认导出全部文件的异常与配对差异，也支持当前视图筛选导出；普通报文查看不会增加异常导出记录。

跳变的 CSV 包含前一报文序号、前一报文序号 HEX、带正负符号的序号数值变化、统计口径、判定提示和候选向前 / 向后跨度。候选跨度不是已确认的回退幅度或丢包数量；TXT 同步使用中性跳变描述，明确分析段数和段间待核对范围。配对仍依据完整帧和接收时间，不受两份日志分段数量不同的影响。

序号默认 HEX 优先，并保留十进制，图表可切换显示进制。原文序号位于 AB 帧偏移 6、7（小端）；详情同时提供“原文字节 → HEX → 十进制”映射和精确字段高亮。缺号只关联前后实际存在的报文字节。CSV 在原有十进制字段后追加 HEX 与小端字节字段，TXT 和复制片段包含同样的对应信息。

分析放在 Web Worker；界面只渲染当前结果页和图表范围。概览聚合同位置的异常标记并显示数量，放大和列表保留逐条访问；绘制简化不影响统计和导出。

完整日志使用可见范围加载，保留每个物理行和原文，不因诊断文字、空行或分片丢失行号。关联原文可以继续浏览到文件首尾；浏览其他行后可返回原异常。图表概览点击最近的实际采样记录，局部放大和上一 / 下一报文访问所有有效记录；当前选择在图中标出。原始与过滤后日志均使用同样的查看能力。

首次加载网页需要联网；加载后可以断网分析。离线缓存、实时蓝牙接入、目录监听、跨设备会话、服务端存储和批量任务不属于首版范围。
