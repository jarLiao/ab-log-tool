# 连接与重连分析

交付版本：1.5.1。范围：连接分段、时间线及序号图上的连接记录；不改变 Android 的过滤规则。

## 查看方式

1. 在“导入日志”选择原始、过滤或配对分析，可附加同一记录任务的 `bleConnection_*.txt`。没有 AB 文件时选择“仅连接诊断”。
2. 原始、过滤视图按连接和待核对的序号边界分段统计；展开分析段表查看原文范围、连接编号、归属依据及段内缺号。图中的“连接区间切换”表示两段有效报文之间的分隔，点击仍定位后一段首包。末条报文之后的断开、会话结束或停止记录也会显示，点击定位相应诊断原文。
3. 左侧“连接时间线”按事件时间列出各个阶段，源行保留记录顺序；时间发生回退时以同一文件的源行核对。连接编号在进程重启后可能复用，因此同时保留进程段。
4. “更多筛选”可选择连接、起止时间。时间线支持按事件类型、连接编号、状态码、源行搜索。点击事件后可浏览完整原文，点击其他行同步变更解析与命令 / Key。
5. “配对比较”展开按连接的汇总表。只在唯一配对锚点成立时关联过滤日志会话；未知归属单独显示。来源前缀用于区分两份文件各自的连接区间，不能把相同编号视作同一连接。
6. 默认全部导出包含独立分析异常、配对差异和连接事件；当前筛选导出只含当前视图。CSV 含连接编号、事件、状态码及全部镜像位置；TXT 保留对应原文片段。原始、过滤、连接诊断三份文件可一并保存到本机历史。

## 判定边界

| 证据 | 网页处理 |
| --- | --- |
| `ble_session ..., connection=..., event=start/end` | 同一文件内优先采用有序收包标记，在边界处清空残帧，重置后续序号统计；真实连接边界不计入“序号跳变待核对”数量。 |
| 标记前出现异步 `disconnected` | 若文件含有序会话标记，等待有序结束位置再切断字节流，允许队列中属于旧连接的片段完成。 |
| 重复 start / end、旧编号的迟到 end | 不反复切段，不切断正在接收的新连接。 |
| `process_start` | 即使连接编号和序号复用，也开始新的统计范围。 |
| 旧版 `Disconnected` / `Link-lossOccur` / `Connected` / `onError` | 识别为诊断文字；没有有序会话标记时按状态边界停止跨连接组包。旧版 Connected 表示应用报告就绪，不能替代恢复收包证据。下一行错误码保留原文位置。 |
| 无连接证据的序号大跨度跳变 | 继续使用既有保守规则，标为待核对，不认定重启、重置或真实回退。 |
| 两份文件中完全相同且各自只出现一次的结构化事件 | 去重展示，保留所有源文件与行号。重复事件文本在单文件内多次出现时不做跨文件去重。 |
| 只有相似时间、相同连接编号 | 不作为跨文件关联证据，不用外部诊断文件的时间戳切断原始报文。 |
| 原始日志含多次连接、过滤日志没有自身边界 | 仅以唯一的接收时间戳和完整帧配对传递会话归属。未匹配或不唯一的报文按未知范围隔离统计，不计为新的已识别连接。 |
| `reorder_skip ..., reason=backward_dup` | 时间戳、序号与原始报文都唯一匹配时，附到对应“仅原始有”记录。其他原因或不唯一记录保留原文，不推断过滤原因。 |

断开与重连统计的粒度是**日志事件**。“断开相关记录”可能包含同一次断线的多个回调，因此不会将它命名为断线次数。错误码属于所在事件，后续重试失败的状态码不能证明此前的断线原因。

同一来源内“断开 → 就绪”优先使用两条记录的单调时钟差；没有单调时钟时使用日志时间，并明确时钟来源。负差值显示未知。手动停止、应用进程重启或可见设备标识变化会结束恢复归因。恢复收包只根据该文件内后续有效 AB 帧判断，不能越过下一次连接尝试、断开、会话结束或进程重启。连接就绪与恢复收包分开说明；单独连接诊断文件缺少报文证据时不会宣称已经恢复数据传输。

每段缺号为零仍不证明整份记录完整。源文件缺失的连接起点、外部未被记录的数据、未知的序号周期，以及非唯一配对关系无法由网页补造。原始文件不做改写，所有分析和历史保存均在当前浏览器本机完成。

## 序号图上的连接记录（1.5.1）

- 横轴为有效报文顺序，按原文行定位连接记录，不按时钟差拉长断开区间。同一报文间隙中的重复回调共用一个图上位置，图下和完整时间线保留各条时间与行号；标记数不是断线次数。
- 区间切换处列出断开、就绪和后一段首包。相同间隙确有断开证据时首包称为“重新收到报文”；缺少断开证据时称为“本段首包”。就绪回调不能替代有效报文证据。
- 最后一条报文之后仍有连接记录时在图末尾显示，并明确“本文件此后无有效报文”。仅有会话结束标记或停止连接记录时按原事件命名，不声称发生链路丢失。断开后仅恢复就绪但没有报文，显示“末尾连接已就绪”及无后续报文提示。
- 分片之间的异步诊断按报文分片位置标注，不误称为末尾断开；缩放只显示当前报文范围内的标记，不把视窗右侧误当作文件末尾。
- 图表只使用当前来源的连接记录，外部诊断文件不能仅凭时间或编号映射到报文。过滤日志通过唯一配对继承的连接区间可显示本段首包，但不借用原始日志的回调行号。
- 图下默认最多展示 6 处记录，优先保留最后一处；每处最多 8 条，超出数量明确提示并提供“完整连接时间线”。窄屏和密集标记优先保留末尾文字，其余标记仍可点击或在文字列表查看。

## 验证

- `node --test tests/engine.test.cjs`：覆盖既有协议、CRC、序号、配对、原文定位，以及跨连接复用、残帧、旧标记、应用重启、事件镜像、恢复状态和唯一配对证据。
- `node scripts/check.cjs`：入口资源、JavaScript 语法、CSP 与本地处理约束。
- `tests/connections.browser.cjs`：三文件导入、时间线、错误码与原文联动、配对证据、CSV/TXT、浏览器重启后恢复三文件、375px 和横屏布局、独立连接诊断与直接打开本地文件。
- 原有 `browser.cjs`、`jump.browser.cjs`、`inspection.browser.cjs`、`history.browser.cjs` 继续覆盖旧版功能。全部结果导出增加连接事件，因此仅核对序号异常的测试显式选择当前视图导出。

浏览器验证依赖 Playwright 和本地 Chrome；通过 `AB_PLAYWRIGHT_PATH`、`AB_BROWSER`、`AB_PREVIEW_URL` 指定环境。真实用户日志、截图和测试导出仅保存在被忽略的 `artifacts/` 下，不进入部署资源。
